# Аккаунты и подписка

Вход на сайт — по одноразовому коду на email, без пароля. Аккаунты, подписки и сохранённые расчёты хранятся в [Supabase](https://supabase.com).

Пока ключи Supabase не заданы, сайт работает как раньше: без входа, все функции бесплатны.

## Как устроено

- **Вход.** Пользователь вводит email, получает код в письме и вводит его на сайте. Аккаунт создаётся при первом входе.
- **Подписка.** В таблице `subscriptions` для каждого пользователя хранится дата, до которой оплачен доступ. Пользователь может только читать свою запись. Записывать её будет сервер после оплаты (этап 2).
- **Платные функции** перечислены в `src/config/plans.ts` (`PREMIUM_FEATURES`). Сейчас это сохранённые расчёты, импорт и экспорт Excel, печать и ссылка на расчёт.
- **Переключатель платного доступа** — поле `paywall_enabled` в таблице `app_settings`. Пока оно `false`, все функции бесплатны, даже для вошедших пользователей.
- **Сохранённые расчёты** вошедшего пользователя хранятся в его аккаунте и доступны на всех устройствах. Расчёты, сохранённые до входа, при входе переносятся в аккаунт. База сама проверяет доступ: без подписки (при включённом переключателе) прочитать или записать расчёты нельзя.
- Остальные платные функции работают в браузере, поэтому ограничение для них — в интерфейсе.

## Подключение

1. **Создайте проект** на https://supabase.com (бесплатного плана достаточно для начала). Регион — ближайший, например Frankfurt.
2. **Создайте таблицы.** Откройте *SQL Editor*, вставьте содержимое файла `supabase/migrations/20261111000000_accounts.sql` и нажмите *Run*.
3. **Настройте письма с кодом.** *Authentication → Emails → Templates*: поправьте **два** шаблона — **Confirm signup** (письмо при первом входе нового пользователя) и **Magic Link** (письмо при следующих входах). В обоих должен быть код `{{ .Token }}`, а не только ссылка. Например:

   ```html
   <h2>Код для входа</h2>
   <p>Ваш код: <strong>{{ .Token }}</strong></p>
   <p>Код действует 1 час. Если вы не запрашивали вход, просто удалите это письмо.</p>
   ```

4. **Подключите свой почтовый сервис (SMTP).** Встроенная почта Supabase отправляет письма только адресам участников проекта и с жёстким лимитом — для настоящих пользователей она не подходит. Пока SMTP не подключён, остальные посетители при попытке входа видят сообщение «Вход в аккаунт сейчас работает в тестовом режиме и временно недоступен». В *Authentication → Emails → SMTP Settings* укажите данные почтового сервиса, например Resend, Brevo или Mailgun.
5. **Укажите адрес сайта.** *Authentication → URL Configuration → Site URL*: `https://zakupi.vercel.app`.
6. **Передайте ключи сайту.** В Vercel: *Project → Settings → Environment Variables* добавьте:
   - `VITE_SUPABASE_URL` — *Project URL* из *Project Settings → API*;
   - `VITE_SUPABASE_PUBLISHABLE_KEY` — *Publishable key* (или устаревший *anon public key*) оттуда же.

   Затем запустите новый деплой — переменные попадают в сайт при сборке.

`service_role` / *secret key* в сайт добавлять **нельзя** — он обходит все проверки доступа. Он понадобится только серверу на этапе оплаты.

Для локального запуска те же две переменные можно положить в файл `.env.local` (он не попадает в git).

## Вход обязателен: ознакомительная страница для гостей

Можно сделать так, чтобы посетители без входа видели только ознакомительную страницу (что умеет калькулятор, пример расчёта и кнопка «Войти по email»), а сам калькулятор открывался после входа.

1. Один раз добавьте переключатель: в *SQL Editor* выполните `supabase/migrations/20261111120000_login_required.sql`.
2. Включите его — **только после того, как подключён свой SMTP** и коды приходят на любые адреса. Иначе посетители не смогут войти:

   ```sql
   update public.app_settings set login_required = true;
   ```

3. Выключить обратно:

   ```sql
   update public.app_settings set login_required = false;
   ```

Ограничение работает в браузере: оно закрывает калькулятор от обычных посетителей, но не является защитой данных — данные аккаунта защищает база.

## Проверка платного доступа до запуска оплаты

Все команды — в *SQL Editor*.

Включить платный доступ:

```sql
update public.app_settings set paywall_enabled = true;
```

Выдать себе подписку на месяц (подставьте свой email):

```sql
insert into public.subscriptions (user_id, plan, paid_until)
select id, 'manual', now() + interval '1 month' from auth.users where email = 'you@example.com'
on conflict (user_id) do update set plan = excluded.plan, paid_until = excluded.paid_until, updated_at = now();
```

Выключить платный доступ обратно:

```sql
update public.app_settings set paywall_enabled = false;
```

После изменений обновите страницу сайта.

## Админ-панель — zakupi.vercel.app/#admin

Всё управление — без SQL, на странице `/#admin`:

- **Заявки** — новые оплаты с кнопками «Подтвердить» / «Отклонить» и история всех заявок;
- **Пользователи** — поиск по email, срок подписки, «+1 / +3 / +12 мес», точная дата окончания, «Отключить»;
- **Тарифы** — цены и показ тарифа;
- **Настройки** — «Платный доступ» и «Вход обязателен».

Открыть может любой, но работать — только администратор: каждое действие выполняет функция базы, которая сначала проверяет, что вошедший email есть в `app_admins`. Остальные видят «Нет доступа».

Подключение: один раз выполните в *SQL Editor* `supabase/migrations/20261111140000_admin_panel.sql` (после миграции оплаты). Администратор назначается так же, как для оплаты, — в таблице `app_admins`. Из окна аккаунта администратора есть ссылка «Админ-панель» с числом новых заявок.

### Пароль админ-панели

После входа по коду из почты панель спрашивает пароль. При первом входе она предлагает его придумать. Пароль хранится в базе только в виде хеша (bcrypt). Правильный пароль даёт сессию на 12 часов в этой вкладке; каждое действие панели база выполняет только с ней. После 5 неверных попыток вход блокируется на 15 минут. Сменить пароль — «Настройки» → «Пароль админ-панели» (при смене все открытые сессии завершаются). Кнопка с замком в шапке панели закрывает её до повторного ввода пароля.

Подключение: выполните в *SQL Editor* `supabase/migrations/20261112000000_admin_password.sql`. До этого админ-панель новой версии сайта не работает.

Если пароль забыт, сбросьте его в *SQL Editor* — при следующем входе панель предложит задать новый:

```sql
delete from public.admin_secrets;
```

## Напоминания об окончании подписки

- **На сайте:** за 3 дня до конца подписки над калькулятором появляется плашка «Подписка заканчивается через N дн. — Продлить», а после окончания (при включённом платном доступе) — «Подписка закончилась».
- **Письмом:** раз в день (в 09:00 по Бишкеку) задача Vercel `api/cron/subscription-reminders.ts` отправляет письмо тем, у кого подписка заканчивается в ближайшие 3 дня. Одно письмо на каждую дату окончания: после продления придёт новое перед следующим концом.

Подключение писем:

1. Выполните в *SQL Editor* `supabase/migrations/20261112000100_subscription_reminders.sql`.
2. В Vercel → *Project → Settings → Environment Variables* добавьте (тип *Sensitive*, окружение *Production*):
   - `SUPABASE_SERVICE_ROLE_KEY` — *Secret key* из Supabase (*Project Settings → API Keys*). Нужен только серверу, в сайт не попадает;
   - `GMAIL_USER` — Gmail-адрес, с которого отправлять письма;
   - `GMAIL_APP_PASSWORD` — пароль приложения этого Gmail (тот же, что в SMTP Supabase, или новый);
   - `CRON_SECRET` — любая длинная случайная строка: Vercel передаёт её задаче, чтобы посторонние не могли её запустить.
3. Запустите новый деплой.

Необязательные переменные: `REMINDER_DAYS` (за сколько дней напоминать, по умолчанию 3) и `SITE_URL` (ссылка в письме, по умолчанию `https://zakupi.vercel.app`). Результат каждого запуска виден в Vercel → *Logs*.

## Оплата подписки по QR-коду

Пользователь платит переводом по QR-коду банка, а администратор подтверждает оплату вручную — банк не сообщает сайту о переводах.

**Как это выглядит для пользователя:** выбирает срок → видит QR, сумму и код платежа (например `ZK-04821`) → переводит деньги в приложении банка, указав код в комментарии → нажимает «Я оплатил». После проверки подписка продлевается: если она ещё действует — к дате её окончания, иначе — от сегодняшнего дня.

### Подключение

1. Выполните в *SQL Editor* `supabase/migrations/20261111130000_qr_payments.sql` — тарифы, заявки на оплату и функции подтверждения.
2. Назначьте администратора — email, с которым вы входите на сайт, строчными буквами:

   ```sql
   insert into public.app_admins (email) values ('admin@example.com');
   ```

3. Включите платный доступ, когда будете готовы брать оплату:

   ```sql
   update public.app_settings set paywall_enabled = true;
   ```

### Подтверждение оплат

Откройте админ-панель (`/#admin`) → «Заявки». Сначала идут заявки, по которым пользователь нажал «Я оплатил». Найдите перевод в банковском приложении по сумме, коду в комментарии и времени и нажмите «Подтвердить» или «Отклонить».

### Цены

Цены хранятся в базе, сайт читает их оттуда — менять можно в админ-панели («Тарифы») или командой:

```sql
update public.subscription_plans set price_kgs = 1900 where id = '6m';
```

Цены в `src/config/plans.ts` используются, только если база недоступна.

### Другой QR-код

Замените картинку `public/payment/mbank-qr.jpg` и данные в `src/config/payment.ts`: ссылку из QR, имя получателя и банк.

### Важно

Принимать оплату за услугу лучше на счёт ИП или организации, а не на личный счёт: уточните у бухгалтера налоговые последствия и лимиты банка.

## Что дальше

Автоматическое подтверждение оплаты через платёжный сервис (например, Finik): серверная функция на Vercel создаёт платёж, а обработчик уведомления проверяет подпись сервиса и продлевает подписку сам.
