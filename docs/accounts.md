# Аккаунты и подписка

Вход на сайт — по одноразовому коду на email, без пароля. Аккаунты, подписки и сохранённые расчёты хранятся в [Supabase](https://supabase.com).

Пока ключи Supabase не заданы, сайт работает как раньше: без входа, все функции бесплатны.

## Как устроено

- **Вход.** Пользователь вводит email, получает код в письме и вводит его на сайте. Аккаунт создаётся при первом входе.
- **Подписка.** В таблице `subscriptions` для каждого пользователя хранится дата, до которой оплачен доступ. Пользователь может только читать свою запись. Записывать её будет сервер после оплаты (этап 2).
- **Платные функции** перечислены в `src/config/plans.ts` (`PREMIUM_FEATURES`). Сейчас это сохранённые расчёты, импорт и экспорт Excel, печать и ссылка на расчёт.
- **Переключатель платного доступа** — поле `paywall_enabled` в таблице `app_settings`. Пока оно `false`, все функции бесплатны, даже для вошедших пользователей.
- **Сохранённые расчёты** вошедшего пользователя хранятся в его аккаунте и доступны на всех устройствах. Расчёты, сохранённые до входа, при входе переносятся в аккаунт. База сама проверяет доступ: без подписки (при включённом переключателе) прочитать или записать расчёты нельзя.
- Остальные платные функции работают в браузере, поэтому ограничение для них — в интерфейсе.

## Подключение

1. **Создайте проект** на https://supabase.com (бесплатного плана достаточно для начала). Регион — ближайший, например Frankfurt.
2. **Создайте таблицы.** Откройте *SQL Editor*, вставьте содержимое файла `supabase/migrations/20261111000000_accounts.sql` и нажмите *Run*.
3. **Настройте письма с кодом.** *Authentication → Emails → Templates*: поправьте **два** шаблона — **Confirm signup** (письмо при первом входе нового пользователя) и **Magic Link** (письмо при следующих входах). В обоих должен быть код `{{ .Token }}`, а не только ссылка. Например:

   ```html
   <h2>Код для входа</h2>
   <p>Ваш код: <strong>{{ .Token }}</strong></p>
   <p>Код действует 1 час. Если вы не запрашивали вход, просто удалите это письмо.</p>
   ```

4. **Подключите свой почтовый сервис (SMTP).** Встроенная почта Supabase отправляет письма только адресам участников проекта и с жёстким лимитом — для настоящих пользователей она не подходит. Пока SMTP не подключён, остальные посетители при попытке входа видят сообщение «Вход в аккаунт сейчас работает в тестовом режиме и временно недоступен». В *Authentication → Emails → SMTP Settings* укажите данные почтового сервиса, например Resend, Brevo или Mailgun.
5. **Укажите адрес сайта.** *Authentication → URL Configuration → Site URL*: `https://zakupi.vercel.app`.
6. **Передайте ключи сайту.** В Vercel: *Project → Settings → Environment Variables* добавьте:
   - `VITE_SUPABASE_URL` — *Project URL* из *Project Settings → API*;
   - `VITE_SUPABASE_PUBLISHABLE_KEY` — *Publishable key* (или устаревший *anon public key*) оттуда же.

   Затем запустите новый деплой — переменные попадают в сайт при сборке.

`service_role` / *secret key* в сайт добавлять **нельзя** — он обходит все проверки доступа. Он понадобится только серверу на этапе оплаты.

Для локального запуска те же две переменные можно положить в файл `.env.local` (он не попадает в git).

## Проверка платного доступа до запуска оплаты

Все команды — в *SQL Editor*.

Включить платный доступ:

```sql
update public.app_settings set paywall_enabled = true;
```

Выдать себе подписку на месяц (подставьте свой email):

```sql
insert into public.subscriptions (user_id, plan, paid_until)
select id, 'manual', now() + interval '1 month' from auth.users where email = 'you@example.com'
on conflict (user_id) do update set plan = excluded.plan, paid_until = excluded.paid_until, updated_at = now();
```

Выключить платный доступ обратно:

```sql
update public.app_settings set paywall_enabled = false;
```

После изменений обновите страницу сайта.
